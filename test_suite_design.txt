Context:
  A Test Suite is a multi-page, chained workflow. It is NOT a flat collection
  of test cases. It represents a real user journey across multiple pages of an
  application — e.g., Login → Goal Sheet → Add 5 Goals → Submit.
  The workflow is visualized as a flowchart with branching paths based on
  test data (user roles, account types, outcome conditions, etc.).

SECTION 1 — CONCEPTUAL MODEL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  TestSuite
  └── has a flow_definition (directed graph: nodes + edges)
      ├── Node = one "step" in the workflow
      │   ├── Linked to: Site → Page → Scenario → TestCases
      │   └── Has position in the canvas (x, y)
      └── Edge = transition between two steps
          └── Has an optional branch_condition
              (e.g., role == "lead", outcome == "passed", data.account_type == "corporate")

  Example flowchart:

    [START]
      │
      ▼
    [Login Page — Auth Scenario]
      │
      ├─── (role = "HR") ──────────▶ [HR Dashboard — View Payroll Scenario]
      │                                      │
      │                                      ▼
      │                              [Submit Report Scenario]
      │                                      │
      │                                      ▼
      │                                   [END]
      │
      └─── (role = "Lead") ────────▶ [Goal Sheet — Add Goals Scenario]
                                             │
                                             ▼
                                     [Goal Sheet — Submit Scenario]
                                             │
                                             ▼
                                          [END]

  Each node maps to ONE TestScenario from an already-analysed Page.
  The engine walks the graph, executes each scenario in order, evaluates
  branch conditions, and follows the correct path.

  3.5  GRAPH WALKER LOGIC (inside process_test_suite_run)
  ────────────────────────────────────────────────────────────────────────────

  def _evaluate_condition(condition: dict, test_data: dict, last_result: str) -> bool:
      """
      Evaluates a branch condition.
      condition = {"field": "role", "op": "eq", "value": "lead"}
              OR  {"field": "_outcome", "op": "eq", "value": "passed"}
      """
      field = condition.get("field")
      op    = condition.get("op")
      value = condition.get("value")

      if field == "_outcome":
          actual = last_result   # "passed" | "failed" | "error"
      else:
          actual = test_data.get(field)

      ops = {
          "eq":  lambda a, b: a == b,
          "neq": lambda a, b: a != b,
          "in":  lambda a, b: a in b.split(","),
      }
      return ops.get(op, lambda a, b: False)(actual, value)


  def _walk_graph(nodes, edges, test_data, execution_results):
      """
      Topological walk of the flowchart.
      Returns an ordered list of node IDs to execute.
      """
      # Build adjacency map
      adj = defaultdict(list)   # source_node_id → [(target_node_id, condition)]
      for edge in edges:
          adj[edge["source"]].append((edge["target"], edge.get("condition")))

      # Find start node
      target_ids = {e["target"] for e in edges}
      start_nodes = [n for n in nodes if n["id"] not in target_ids]

      execution_order = []
      visited = set()
      queue = deque(start_nodes)

      while queue:
          node = queue.popleft()
          if node["id"] in visited:
              continue
          visited.add(node["id"])
          if node["data"]["node_type"] not in ("start", "end"):
              execution_order.append(node["id"])

          last_result = execution_results.get(node["id"], "passed")
          candidates = adj[node["id"]]

          if not candidates:
              continue
          # Filter edges that have no condition — always follow
          unconditional = [(t, c) for t, c in candidates if c is None]
          conditional   = [(t, c) for t, c in candidates if c is not None]

          followed = False
          for target, cond in conditional:
              if _evaluate_condition(cond, test_data, last_result):
                  queue.append(_node_by_id(nodes, target))
                  followed = True
                  break

          if not followed:
              for target, _ in unconditional:
                  queue.append(_node_by_id(nodes, target))

      return execution_order

  4.1  FLOWCHART LIBRARY CHOICE — React Flow (reactflow)
  ────────────────────────────────────────────────────────────────────────────

  Recommended: @xyflow/react (React Flow v12)
  Package:     npm install @xyflow/react

  Why React Flow over draw2d:
    - draw2d is a jQuery-era library (last release 2020). No React support.
    - React Flow is the modern standard, React-native, TypeScript-first,
      actively maintained, and purpose-built for node-edge diagrams.
    - Supports custom nodes, custom edges, and programmatic layout.
    - Has built-in minimap, controls, and background components.
    - Works with React 19.

  4.6  TestSuiteBuilder.tsx — FLOWCHART CANVAS
  ────────────────────────────────────────────────────────────────────────────

  This is the core component. It renders the React Flow canvas.

  State:
    nodes: Node<FlowNodeData>[]   — from suite.flow_definition.nodes
    edges: Edge[]                 — from suite.flow_definition.edges
    isDirty: boolean              — unsaved changes
    selectedNode: string | null
    selectedEdge: string | null

  On load:
    Fetch suite by ID → initialise nodes + edges from flow_definition.
    If flow_definition is null → initialise with [START node] + [END node].

  Node types registered with React Flow:
    "start"  → StartNode  (green circle, no delete button, not connectable as target)
    "end"    → EndNode    (red circle, no delete button, not connectable as source)
    "step"   → StepNode   (card showing page title + scenario title + status badge)

  Edge types registered with React Flow:
    "condition" → ConditionEdge  (shows label if condition set, edit button on hover)

  Toolbar actions (SuiteToolbar):
    [+ Add Step]   → adds a new blank StepNode at the centre of the canvas
    [Save]         → calls api.update with current nodes/edges as flow_definition
                     + re-syncs TestSuiteStep rows on backend
    [Mark Ready]   → sets suite.status = "ready" (validates all nodes have scenario)
    [Run]          → opens TestSuiteRunPanel / trigger run dialog
    [← Back]       → navigates back to list (warns if isDirty)

  Node interactions:
    Double-click node  → opens EditStepDialog to set page + scenario
    Click delete on node → removes node + its connected edges
    Drag node          → React Flow built-in, updates position in state

  Edge interactions:
    Double-click edge  → opens EditEdgeDialog to set branch condition
    Click delete on edge → removes edge

  Validation before "Mark Ready":
    - All step nodes must have page_id + scenario_id set
    - Graph must be connected (no orphaned nodes)
    - Graph must have exactly one START and one END node

  class TestSuiteExecutionService:

    def run(self, suite_id, run_id, test_data, requested_by):
      db = SessionLocal()
      try:
        run = db.query(TestSuiteRun).filter_by(id=run_id).first()
        run.status = "running"
        run.started_on = datetime.utcnow()
        db.commit()

        suite = db.query(TestSuite).filter_by(id=suite_id).first()
        flow  = suite.flow_definition  # dict with nodes + edges

        # Walk the graph → ordered list of node_ids to execute
        execution_order = _walk_graph(flow["nodes"], flow["edges"],
                                       test_data, {})

        results = {}    # node_id → "passed" | "failed" | "error"
        summary = {"total": 0, "passed": 0, "failed": 0, "skipped": 0}

        for node_id in execution_order:
          node = _node_by_id(flow["nodes"], node_id)
          scenario_id = node["data"].get("scenario_id")
          if not scenario_id:
            results[node_id] = "skipped"
            summary["skipped"] += 1
            continue

          # Retrieve scenario + page
          step_result = TestExecutionService(
              llm=LLMWrapper(db=db),
              prompt_manager=PromptManager(),
              logger=logger,
          ).execute_scenario(
              scenario_id=scenario_id,
              requested_by=requested_by,
              test_suite_id=suite_id,
              test_suite_run_id=run_id,
          )

          outcome = "passed" if step_result["passed"] else "failed"
          results[node_id] = outcome
          summary["total"]  += step_result["total"]
          summary["passed"] += step_result["passed_count"]
          summary["failed"] += step_result["failed_count"]

          # Re-evaluate graph with updated results for branching
          execution_order = _walk_graph(flow["nodes"], flow["edges"],
                                         test_data, results)

          # Notify WebSocket after each step
          self._notify_suite_ws(run_id, suite_id, outcome, summary, requested_by)

        # Determine final status
        if summary["failed"] == 0:
            final = "passed"
        elif summary["passed"] > 0:
            final = "partially_passed"
        else:
            final = "failed"

        run.status = final
        run.completed_on = datetime.utcnow()
        run.execution_summary = summary
        db.commit()

      finally:
        db.close()

  NOTE: execute_scenario() is a new method to add to TestExecutionService
  that runs all test cases for a single scenario and returns aggregate counts.
